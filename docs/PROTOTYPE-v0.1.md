# 可运行原型说明 · V0.1

## 当前实现范围

这是一个**没有 AI、数据库和 Web 服务**的 TypeScript 离线规则引擎原型。核心代码在 [src/engine.ts](../src/engine.ts)，测试在 [tests/engine.test.ts](../tests/engine.test.ts)。

它包含：

- 数学学习记录（解题、复习、跨学科学习）结构化输入。
- 显性熟练度、可变隐藏特性、疲劳、研究次数和跨领域关联。
- 确定性非线性熟练度成长。
- 白名单规则字段、条件判定、可配置加法概率、一次抽样、冷却及机会次数限制。
- 防重提交（内存幂等）、UTC 活动时间重叠检测、每日四小时上限。
- 模拟内的研究线索事件，与真实个人经历严格区分。
- 一键生成 1,000 个**纯虚构**角色，在两种行动脚本下分别运行 120 天；每种脚本各处理 120,000 条生成事件。

## 运行

需要 Node.js **22.16.0 或更新的 Node 22 版本**及 npm；运行时不需要 AI API 或 GPU。

~~~bash
npm install
npm run typecheck
npm test
npm run simulate
# 可选：指定可复现的测试种子
npm run simulate -- --seed another-seed
# 或一次执行全部：
npm run verify
~~~

运行测试使用 Node 内置测试框架和 TypeScript 类型擦除。依赖仅 TypeScript 开发工具；模拟和规则逻辑不依赖第三方运行时包。

## 离线平衡实验

`npm run simulate` 使用种子 `earth-online-v1`，生成 1,000 个虚构角色及其初始数学值、学习适应性和关联思维。每个角色在两个配对情景中使用相同初始值、事件 ID 与抽样函数，每天学习 90 分钟，共 120 天：

- **混合学习：** 每四天一次跨领域学习；其余日子每五天复习，否则解题。
- **不跨领域：** 每五天复习，其余日子解题。总投入时间相同，但行为组合不同。

示例输出（种子和规则版本不变时 JSON 结果可复现）：

| 指标 | 混合学习 | 不跨领域 |
| --- | ---: | ---: |
| 虚构角色 / 输入事件 | 1,000 / 120,000 | 1,000 / 120,000 |
| 至少一次满足所有规则条件的角色 | 1,000 | 0 |
| 满足条件的事件 / 规则尝试 | 78,326 / 11,302 | 0 / 0 |
| 因冷却或尝试配额未抽样的合格事件 | 67,024 | 0 |
| 模拟研究线索 / 获得至少一条线索的人数 | 373 / 315 | 0 / 0 |
| 最终数学熟练度平均 | 89.75 | 90.63 |

混合学习中，685 人没有线索、262 人有一条、53 人有两条或更多。初始关联思维较低组 527 人中 147 人获得线索，较高组 473 人中 168 人获得线索；两组均有成功和未成功的角色。初始潜变量、具体抽样和达到前置条件的时间都会影响结果，不能仅凭这一实验推断各因素的独立作用。

不跨领域脚本中的角色虽然都达到数学与研究次数门槛，却没有跨领域关联，因此无法尝试这条规则。这揭示的是**当前单条跨领域规则的必要条件**；是否增加其他路径仍是设计问题。两组均达到较高熟练度，提示当前每天持续学习的假设和成长曲线值得进一步调参。输出还包括固定参考门槛覆盖、条件命中、配额抑制和按初始关联思维分组的数据。运行时间写入标准错误，因为它受机器与系统负载影响，不属于可复现结果。

这些数字只体现当前规则、两种固定脚本、虚构初始属性和公开的测试抽样函数，不是经校准的平衡结论或真实人生科研成果概率。输入事件中的 `self_reported` 是现有原型协议字段，实验全部由程序生成；产出的线索是 `system_simulated`、等待选择的游戏内容，不是真实发现。公开种子的哈希函数只用于离线复现，不能用于正式服务抽奖。

## API 级函数

- `createWorld(id, initialMath, learningAdaptation, associativeThinking)`
- `validateEvent(world, event)`
- `applyProgression(character, event)`
- `validateRule(rule)`
- `evaluateRules(character, event, rules)`
- `processEvent(world, event, rules, roll?)`

`processEvent` 会返回新世界状态，不会修改旧对象；同一幂等键用于不同内容时会报错。调用方仍需将世界状态视为不可变数据。规则配置示例见 [math-insight.json](../examples/rules/math-insight.json)。

## 已知限制（禁止直接接入真实用户开放服务）

1. **内存状态：** 断电即丢失；幂等仅在当前进程有效，不支持并发事务。
2. **尚无账户认证、数据库、隐私隔离、实时多人通信或管理员审核。**
3. **只有一条数学领域规则。** 当前引擎不是全学科通用游戏，也尚未实现成就系统或玩家关系系统。
4. 概率参数、成长曲线、跨领域联系均为游戏设计假设，尚未调参验证。
5. 离线模拟使用公开可预测的哈希随机源，仅为了测试复现；游戏实服抽签应使用服务端安全 RNG，第一次结果写入事务日志，并保护客户端不可操作。
6. `applyProgression`、`evaluateRules` 是纯计算函数；`processEvent` 还未实现数据库锁、outbox、历史规则版本重放或多端重复提交。
7. 事件输入仅表示玩家自述，不能自动视为经过现实认证的事实。
8. 原型将每次「解题」计作一次研究活动；这只是方便实验的简化规则，还不是完整的研究行为建模。

## 下一步（按优先级）

1. 把引擎转换为依赖最小、可测试的独立 domain 模块；逐步支持更多领域与事件类型。
2. PostgreSQL 持久化：角色、事件、规则尝试、际遇，含幂等唯一约束和事务。
3. 实现明确的成就条件与解锁，不让自由录入直接解锁真实世界奖项。
4. 建立最小网页入口与事件表单、角色面板和时间线。
5. 逐步加入角色关系、双向同意与共享事件；以离线批量实验持续调优。

## 与现有设计文档的关系

[EVENT-ENGINE-v0.1.md](EVENT-ENGINE-v0.1.md) 是**目标协议**；本原型是其可运行子集。

文档中的 `attribute.add`、`event.emit`、`achievement.unlock` 等效果尚未实现；目前只实现 `encounter.create`。规则样例已调整为引擎支持的字段集合（例如 `chance.model = additive`）。请勿将需求文档所有功能理解为已交付。

原型仅支持 `all` 条件与 `gte`、`lte`、`eq` 比较，以及示例中的限定路径；概率修正项只接受归一化关联思维或新视角布尔值。`event.context.new_perspective` 在此由跨领域学习方式推导。规则协议中的其他条件与路径仍待实现。
