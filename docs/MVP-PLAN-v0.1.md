# 地球 Online · MVP 开发方案 V0.1

> 本文将 [产品需求](PRD-v0.1.md) 与 [核心机制](CORE-MECHANICS-v0.1.md)、[事件协议](EVENT-ENGINE-v0.1.md) 变为可执行的开发任务。当前仓库处于**设计阶段**，下列内容是开发方案，不表示功能已经实现。

## 1. MVP 要回答的问题

**玩家只通过结构化行为输入，是否能在不使用 AI 的情况下，体验到可解释的、带有个体差异的成长、随机际遇和成就？**

不要在这一阶段同时验证大型多人社交网络、文明经济模型或真实人生预测。

### 目标玩家流程

~~~text
进入网站 → 创建角色 → 选择初始兴趣
→ 记录「数学分析练习 90 分钟」
→ 查看技能增长和习惯进度
→ 查看新出现的际遇或待解锁条件
→ 选择「继续研究 / 与人交流（先作为单人游戏内行动）」
→ 通过后续行动解锁研究线索或成就
→ 在人生时间线查看事件间的关联
~~~

## 2. 第一版功能范围

| 优先级 | 功能 | 完成标准 |
| --- | --- | --- |
| P0 | 账号与本人角色 | 可以安全创建、查看与删除角色 |
| P0 | 可见技能、隐藏特性 | 值域校验、初始化可复现、他人不可读取 |
| P0 | 行为输入 | 至少支持学习、阅读、探索、创作、日常生活五类 |
| P0 | 确定性成长 | 成长/衰减随行为变化，同一状态与输入计算结果一致 |
| P0 | 规则配置与引擎 | 可从 JSON 加载规则并拒绝非法配置 |
| P0 | 概率抽样与冷却 | 可重复测试、不重抽、阻止短期高频刷取 |
| P0 | 随机际遇与选择 | 至少支持创建待选择事件和一种后续分支 |
| P0 | 成就图鉴 | 普通、隐藏、积累三类成就可解锁 |
| P0 | 人生时间线 | 显示事件来源、主要影响和已触发成就 |
| P0 | 自动模拟测试 | 不依赖 AI 服务，能离线模拟 1,000 个虚构角色 |
| P1 | 真人关系与同意 | 双方确认后才能生成共享事件 |
| P1 | 知识传播与多人任务 | 玩家间分享、协作推动游戏状态 |
| P2 | 公共世界状态演化 | 世界事件及长期知识传播 |

### 第一版建议内容规模

- 6 个领域：数学、语言、创造、探索、生活、社交（社交 P0 只记录个人体验，P1 才进行真实多人关系）。
- 约 20 项可见熟练度、12 项内部特性。
- 约 20 条结构化行为模板。
- 约 30 条事件或际遇规则。
- 约 40～50 项成就。
- 1 条可完成的数学研究线索任务链。

以上是内容制作预算的建议，而非系统必须达到的魔法数字。先跑通一条端到端链路，再扩充内容。

## 3. 技术结构

~~~text
Next.js + TypeScript 网页
     │
     ├── 角色创建 / 技能档案 / 事件输入 / 成就 / 时间线
     │
     ▼
后端 API（初版同一 Node.js 服务即可）
     │
     ├── 事件验证器
     ├── 纯函数成长计算器
     ├── 规则筛选与执行器
     ├── 随机尝试与幂等管理
     ├── 时间线与成就读取
     │
     ▼
PostgreSQL
     ├── 角色 / 属性 / 事件 / 规则
     ├── 尝试日志 / 际遇 / 成就
     └── 审计 / outbox / 任务
~~~

可先使用数据库 outbox + 简单后台任务；只有在实际吞吐与异步需求增加时再引入 Redis/消息队列。

代码目录**建议**：

~~~text
src/
  app/                       # 页面与 API
  domain/
    characters/              # 属性、特性与角色规则
    progression/             # 经验、节点、衰减
    events/                  # 事件协议与校验
    rules/                   # 条件 DSL 与执行器
    encounters/              # 际遇及选择
    achievements/            # 成就判定
  infrastructure/
    db/                      # 数据库访问、迁移、事务
    tasks/                   # outbox 与定时结算
tests/
  unit/
  integration/
  simulation/
docs/
examples/rules/
~~~

domain 目录不得依赖浏览器组件或具体数据库客户端，以便对同一输入进行离线回放。

## 4. 按垂直切片开发

### M0：工程底座

- 初始化 TypeScript、Next.js、PostgreSQL 访问和测试框架。
- 建立 schema 迁移、基础 lint 与 CI。
- 实现开发用规则配置校验命令。
- 制定公开 API 的鉴权边界。

**验收：** 本地一条命令运行测试；数据库迁移可从空库成功执行；没有任何 AI SDK/API 依赖。

### M1：单人角色与属性

- 实现角色初始化，生成并持久化游戏潜变量。
- 初始化 6 个领域与第一批知识节点。
- 仅返回显性属性给普通前端。
- 添加技能值域和成长边界测试。

**验收：** 相同初始化种子可复现；不同种子可产生合理差异；隐藏特性不会被本人公开接口或其他玩家接口泄漏。

### M2：记录事件与确定性成长

- 设计第一个学习事件：科目、方式、时长、发生时间。
- 落地时长预算、重复提交、时间重叠检测。
- 处理事件后写入知识成长和事件时间线。
- 幂等接口，重试不重复增长。

**验收：** 同一事件重复提交 10 次仍只结算一次；行为超过时长预算被拒绝；正常成长可解释。

### M3：规则与概率际遇

- 实现事件类型订阅索引与规则 DSL 求值。
- 加入概率、冷却、抽样审计。
- 实现「数学跨领域研究线索」规则与一次主动选择。
- 限制派生事件深度和数量。

**验收：** 条件不满足时绝不触发；满足条件时按配置概率进行一次抽样；同一事件重放结论不变；连锁事件不会无限循环。

### M4：成就与玩家体验

- 至少提供「首次记录」「连续积累」「隐藏研究线索」三种成就。
- 完成角色面板、事件提交、待办际遇、成就图鉴和时间线。
- 显示「现实自述」和「游戏模拟」的不同标识。
- 保持隐藏变量不直接显示，但结果说明仍可理解。

**验收：** 玩家从创建角色到获取第一次成就，无需阅读技术文档；界面不会将模拟线索冒充真实学术发现。

### M5：平衡、安全与预发布

- 自动生成行为脚本并执行成批虚构角色。
- 测试规则覆盖率、事件分布、冷却与刷取风险。
- 基础访问控制、个人记录导出与删除。
- 为管理员提供事件重放与规则版本查询。
- 灰度发布前评估异常规则与成就可达性。

**验收：** 无可重复领取的奖励漏洞；无私人数据越权读取；1000 角色离线模拟不依赖外部 AI API；每项重要际遇均可解释。

## 5. 示例行为与成就清单

| 行为模板 | 必填字段 | 确定性成长 | 可能的后续机会 |
| --- | --- | --- | --- |
| 学习数学 | 知识节点、方法、分钟 | 数学节点熟练度 | 研究线索 |
| 阅读一本书 | 领域、阅读分钟 | 阅读/领域经验 | 交叉知识关联 |
| 徒步活动 | 地形类别、分钟 | 户外经验 | 新探索任务 |
| 学习烹饪 | 菜系/技能、分钟 | 烹饪熟练度 | 新技能解锁 |
| 创作作品 | 类型、创作分钟 | 创作经验 | 作品展示任务 |

MVP 里不要把「徒步」自动换算成真实身体健康或免疫力变化；只能形成明确的游戏经验和虚构机制。

建议成就：

- 【你好，地球】创建角色。
- 【新的知识】首次完成有效学习记录。
- 【重复的力量】在不同日期完成多次练习。
- 【初级探索者】完成多个不同的探索模板。
- 【知识交汇】解锁第一条跨学科关联。
- 【灵光一现】完成一次研究线索际遇（游戏内；不代表科研证明）。
- 【持续求索】完成多阶段研究任务。

## 6. 可量化的质量门槛（初步目标）

| 指标 | 第一版目标 |
| --- | --- |
| 核心链路测试 | 创建 → 提交 → 成长 → 规则 → 时间线全部通过 |
| 事件幂等 | 同一事件重复执行效果次数 = 1 |
| 隐藏数据访问 | 未授权访问成功次数 = 0 |
| 数据完整性 | 所有已触发效果均存在关联事件与规则版本 |
| 异步任务 | 相同 outbox 任务重放不会造成重复效果 |
| 模拟测试 | 至少 1,000 个虚构角色可批量离线运行 |
| 规则覆盖 | 所有已发布规则存在条件命中/未命中的测试 |
| 人生真实性 | UI 不把游戏虚构际遇宣称为真实人生事实 |

性能目标（如 P95 响应时间）需在实现后根据部署环境和容量测试确定，暂不伪造一个没有依据的指标。

## 7. 设计风险与缓解

| 风险 | 对策 |
| --- | --- |
| 用户虚假填报或刷时长 | 输入校验、逐日时间预算、重复检测、渐进回报封顶 |
| 属性组合过多难平衡 | 少量初始属性、离线批量模拟、规则测试覆盖 |
| AI 缺席导致输入太繁琐 | 一键复用事件模板、常用选项、快捷记录 |
| 事件持续触发造成成本失控 | 冷却、候选索引、惰性计算、链路深度与数量限制 |
| 用户误解模拟结果为现实预测 | 明示来源、解释机制、避免医学或人生诊断 |
| 隐藏属性产生出生决定论 | 训练可塑性、环境机会、多条可行成长路径 |
| 稀有事件成为纯抽奖 | 必要积累、研究任务链、可解释的失败价值 |
| 社交功能侵犯隐私 | P1 才加入，双方同意、私密默认、删除与屏蔽 |

## 8. 未定决策与默认建议

1. **现实映射还是平行模拟：** MVP 使用「真实行动记录 + 独立游戏模拟际遇」，界面显式区分。
2. **初始特性：** 游戏内部随机且可随行为改变；不根据用户敏感个人资料推断潜能。
3. **时间：** 使用现实时间，只在测试模拟器中启用加速时间。
4. **自由文字：** 作为私人备注，暂不用于计算。
5. **社交：** P0 无需玩家实时匹配；P1 再做真人邀请与双方确认。
6. **成就：** 以不同路径的个人成长为主，不设强制全服统一排名。
7. **世界事件：** 先用管理员配置的简单事件，不做完整全球经济或文明推演。

## 9. 下一份应该写的代码

优先实现一个**可离线测试的 TypeScript 纯函数包**，暴露三个入口：

~~~typescript
validateEvent(input, character, history) // 校验结构化行为
applyProgression(character, event)         // 必然属性变化
evaluateRules(character, event, rules)    // 条件与候选概率，不自行改数据库
~~~

随机抽样与效果持久化放在上层编排器，确保同一事件重试不重抽。第一条演示用例就是仓库中的 [数学顿悟配置](../examples/rules/math-insight.json)。

**开发成功的标志：不是造出更多剧情，而是让有限规则产生可信、一致、可解释、可长期扩展的游戏反馈。**
