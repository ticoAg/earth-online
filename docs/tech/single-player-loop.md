# 离线单人闭环实现规格

本文描述已实现的离线单人闭环。阶段完成状态和验证记录见[路线图](../product/roadmap.md)；账户、数据库与网页仍未实现。

## 依据与边界

- [产品需求](../PRD-v0.1.md)：行为记录、模拟际遇、成就和人生时间线。
- [MVP 方案](../MVP-PLAN-v0.1.md)：M3 的主动选择、M4 的三类最小成就与来源标记。
- [原型说明](../PROTOTYPE-v0.1.md)：当前实现与内存状态限制。
- [现有引擎](../../src/engine.ts)：`World`、`Encounter`、`processEvent` 和角色归属约束。

本阶段在 TypeScript 离线内存模型内完成「学习 → 成长 → 际遇 → 选择 → 成就 → 时间线」闭环。现有学习输入和概率规则继续适用。数据库事务、账户认证、网页和真人交流分别在后续阶段实施。

接口与状态以源码为依据[^engine]；闭环目标来自 MVP 设计[^mvp]，当前交付边界来自原型说明[^prototype]。

## 1. 际遇选择

新增选择命令 `EncounterChoice`，字段为 `id`、`actorId`、`encounterId`、`choice`、`occurredAt`、`idempotencyKey`。`choice` 限定为 `continue_research` 或 `archive`；输入日期沿用学习事件的严格 UTC 日期校验，必须为有效时间且不早于来源事件的结束时间。

将际遇状态扩展为 `pending_choice | resolved`。结算保存选择、选择事件 ID、结算时间；保留 `sourceEventId`、规则 ID、规则版本、`system_simulated` 和 `unverified`，允许追踪线索起因。旧际遇缺少规则版本时，从匹配的来源事件尝试记录读取，找不到时拒绝结算并报告状态不完整。

提供纯编排入口 `resolveEncounter(world, command)`，返回新世界及稳定的选择结果。校验角色归属、际遇存在、选项合法、状态和时间后再修改状态：

| 选择 | 结算结果 | 玩家解释 |
| --- | --- | --- |
| `continue_research` | 际遇标记已处理，授予游戏内隐藏线索成就 | 你选择继续探索这条游戏研究线索；尚未证明任何真实结论 |
| `archive` | 际遇标记已处理，记录归档选择 | 线索已归档，本次不再结算 |

选择不增加学习时长、数学熟练度或研究次数，也不重新抽样。继续研究只是单人游戏行动；后续多阶段研究链由未来阶段扩展。

## 2. 三类最小成就

成就存储使用稳定定义 ID、定义版本、解锁时间、来源事件 ID、来源类型；每个角色每项定义只解锁一次。

| 定义 ID | 类别 | 精确条件 | 解锁时间 |
| --- | --- | --- | --- |
| `first_record` | 普通 | 首次接受有效学习事件 | 达成事件开始时间 |
| `steady_practice` | 积累 | 已接受学习事件覆盖至少 3 个不同 UTC 日期，无需连续 | 第三个日期对应的达成事件开始时间 |
| `research_lead` | 隐藏 | 对 `research_lead` 际遇成功结算 `continue_research` | 选择命令时间 |

行为次数仅基于已接受事件；重复请求、被拒绝输入、随机抽样失败和归档选择不额外计数。学习命令结束后计算前两项，选择命令结束后计算第三项。并列达成的成就按定义 ID 排序，保证结果可复现。

历史回放不得重新套用未来修改后的成就定义。命令结果保留此次新增成就；重试返回首次结果快照。未来持久化层需保存定义版本及历史结算证据。

## 3. 统一时间线与公开投影

提供只读 `getTimeline(world)`，从已接受学习事件、际遇及已结算选择、成就生成条目，不改变世界状态。条目至少有稳定 ID、时间、类型、来源事件 ID、来源标记和解释。相同时间使用类型顺序（学习、际遇、选择、成就）后按 ID 排序。

- 学习：显示 `self_reported`，表示现实行为自述；显示数学熟练度变化与时长。
- 际遇、选择与成就：显示 `system_simulated`，表示游戏系统结果；际遇保留 `unverified`。
- 来源链接可在条目之间追踪，但不公开隐藏特性、概率修正值、随机数或内部尝试日志。

学习增长说明应使用首次结算结果中保存的 `delta`，不得根据当前熟练度回算。现有 `idempotency` 保存结果，可供本阶段投影读取；投影通过事件 ID 关联，不能依赖幂等键等于事件 ID。

公开角色读取另设白名单投影，仅提供角色 ID、可见熟练度、待处理际遇、成就与时间线。`World` 是内部离线模型，不能直接作为未来 HTTP 响应返回。

## 4. 幂等、原子性与兼容

学习与选择共用角色范围的命令幂等登记，登记项保存命令类型、规范化输入与首次结果。比较输入采用显式字段或稳定序列化，拒绝相同键对应不同类型或不同内容。键允许普通字符串，使用 `Object.hasOwn` 或 `Map`，避免原型链属性误判。

执行顺序为：校验角色归属 → 查找幂等结果并比较输入 → 验证命令及当前状态 → 构造新状态并计算成就 → 保存命令及结果。原对象和历史返回结果均不可因后续调用或调用方修改而变化。

相同选择命令重放返回首次结果，不二次授奖；不同键再次选择已处理际遇返回 `encounter_already_resolved`。同键更改目标或选项返回 `idempotency_conflict`。失败命令不写入状态；后续修正后可重新提交。

现有 `processEvent` 保留原有结果字段，并增加本次解锁成就。旧世界缺少新集合时按空集合处理；读取或选择不会追溯授予旧学习成就，下一次有效学习时才按全部已接受的学习记录判断缺失成就，并以该次事件作为解锁依据。本阶段不声称支持跨进程幂等或并发事务。

## 5. 实现顺序与验收

1. 扩展领域类型、初始化和兼容适配，保留现有学习与模拟行为。
2. 实现选择命令及统一幂等登记；一次命令在内存内完成状态和奖励更新。
3. 实现成就判定和历史结果快照。
4. 实现时间线及公开角色投影，补充一个完整离线示例。

阶段验收使用 Node 内置测试，覆盖真实行为约束和失败路径：

- 控制随机源产生一条研究线索，选择继续研究后状态、隐藏成就和时间线完整关联；归档路径不授予隐藏成就。
- 原选择重试 10 次，状态和奖励数量不变；同键更改内容、学习与选择跨类型复用键、不同键重复选择均按约定拒绝。
- 错误角色、未知际遇、非法选项、无效时间及早于来源事件的选择不改变输入世界。
- 3 个不同 UTC 日期解锁积累成就；同日多次和重复提交不满足日期门槛。
- 学习、选择、成就同时间时输出稳定；所有条目有来源标记，公开投影无隐藏值和抽样细节。
- 修改返回结果不能影响后续重放或时间线；旧学习测试与离线模拟保持通过。

阶段验收结果和兼容限制记录在[路线图](../product/roadmap.md)。
