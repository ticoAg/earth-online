# 需求与分阶段研发路线

本路线把 [PRD](../PRD-v0.1.md)、[核心机制](../CORE-MECHANICS-v0.1.md)、[事件协议](../EVENT-ENGINE-v0.1.md) 和 [MVP 方案](../MVP-PLAN-v0.1.md) 组织成可独立验收的交付阶段。旧文档中的功能清单是目标设计；当前实现证据见 [原型说明](../PROTOTYPE-v0.1.md)。

## 当前基线

截至 2026-10-30，仓库具备 TypeScript 单人离线原型：数学学习、非线性成长、配置规则、概率际遇与选择、三类最小成就、公开投影、内存幂等和配对模拟。另有本地 SQLite 学习事件持久化和自治世界调度原型，详见 [SQLite 说明](../DATABASE-SQLITE-D1-v0.2.md)和[世界运行说明](../WORLD-IMPLEMENTATION-v0.2.md)。源码是 [engine.ts](../../src/engine.ts)、[projection.ts](../../src/projection.ts) 和 [runtime.ts](../../src/world/runtime.ts)。

研究线索可以在内存中继续探索或归档；完整研究任务链、选择持久化、账户、网页及多人关系仍待实现。现有 SQLite 原型不满足开放服务的完整持久化和访问隔离条件。

状态含义：`已实现子集` 表示仅有明确列出的原型能力；`进行中` 表示当前切片；`待实现` 表示未验收；`远期` 表示依赖 MVP 的探索范围。阶段完成需要保存命令、结果和实现链接，不能以文档写完代替功能验收。

## 阶段、依赖与退出条件

依赖主线：`S0 → S1 → S2 → S3 → S4 → S5 → S6`。每个阶段内部先跑通最小垂直链路，再扩充内容；建议内容数量不作为阻塞首个闭环的硬指标。

### S0：文档和可执行基线（本轮完成）

- 建立 OKF 文档入口、当前状态、需求编号与阶段记录。
- 保留现有设计作为背景，明确目标协议与原型实现的区别。
- 退出条件：新开发者能从统一入口找到需求、当前切片、验证命令与已知限制；链接和文档元数据检查通过。

### S1：单人离线玩法闭环（已完成）

涉及 EO-001～EO-006、EO-011。复用现有引擎，补充待选择际遇的处理、明确的游戏奖励、成就解锁和可公开的结果说明。首个切片优先补际遇选择，因为原型已经产生等待选择状态。实现细节见[单人闭环实施规格](../tech/single-player-loop.md)。

- 退出条件：自动化用例覆盖学习→际遇→选择→游戏奖励，重复请求不重复结算；不同选择结果有明确定义；旧状态不被修改。
- 阶段最终验收：普通、积累、隐藏成就各至少一种；公开视图不泄漏隐藏状态；来源能区分自述与模拟；现有规则和模拟回归通过。
- 阶段范围仍是离线内存模型。完成此阶段不代表账户、事务或可开放服务。

完成记录（2026-10-30，EO-001～EO-006、EO-011 的上述子集）：`processEvent` 和 `resolveEncounter` 接受学习或选择命令，返回新世界及首次结算快照；`getTimeline` 和 `getPublicCharacter` 返回白名单投影。学习、选择、三类成就、归档、冲突和失败不修改旧状态均有自动化覆盖。`npm run verify` 通过类型检查、32 项测试和两组各 1,000 个角色的模拟；默认种子下线索数量仍为 373 / 0，与原基线一致。`npm run example` 可运行虚构角色的完整示例，`git diff --check` 和本地文档链接检查通过。旧世界缺少新增集合时，历史学习成就在下一条有效学习时惰性判断；持久化、并发事务和完整任务链仍未实现。

### S2：持久化与私有角色服务

涉及 EO-003、EO-007、EO-008、EO-010。现有 SQLite 原型提供迁移及学习事件的事务提交、并发检查和历史查询；后续对接本地 D1，并补齐角色归属、受信任身份边界、选择及成就持久化。

- 依赖：S1 的事件和选择结算契约稳定。
- 退出条件：空库迁移成功；重启后状态可读；同一请求并发提交只生效一次；处理中故障不会留下部分奖励；跨账号读写被拒绝。
- 事件、规则版本、尝试、际遇与成就保留关联；历史结果读取不依赖当前规则重新抽样。导出和删除行为先确定关联数据处理契约，再接入网页。

### S3：单人网页体验

涉及 EO-006、EO-009。提供角色创建、档案、学习表单、际遇选择、成就和时间线；服务端仅返回允许公开给本人的字段。

- 依赖：S2 的授权与持久化接口。
- 退出条件：浏览器端完成创建→记录→成长→际遇→选择→成就；刷新后保留结果；重试无额外奖励；必填错误与服务失败可恢复。
- 页面明确标记现实自述和游戏模拟；游戏线索不展示为真实科研成果或真实奖项。

### S4：内容扩充与 MVP 预发布

涉及 EO-001、EO-002、EO-004、EO-005、EO-010、EO-011。扩充学习、阅读、探索、创作、生活五类输入，一条完整数学研究任务链，并验证数据生命周期、异常规则和防刷。

- 依赖：S3 的可玩单人链路。
- 退出条件：五类行为均有成功与拒绝用例；每条发布规则具备条件命中/未命中测试；三类成就可达且不重复；1000 个虚构角色离线模拟无需 AI 服务。
- 本人数据导出和删除可验证；跨账号负面测试通过；各重要际遇可以追踪事件和规则版本。性能目标在实际部署环境测量后确定。

### S5：双方同意的多人协作

涉及 EO-012。先实现邀请、接受、撤销、屏蔽和共享事件，再实现知识分享、合作任务、共同成就。

- 依赖：S4 MVP 验收和私有数据生命周期完成。
- 退出条件：双方确认前不写入共享关系；共享记录只暴露授权字段；重试不重复发奖；撤销与屏蔽后的权限行为有测试。

### S6：共享世界与长期演化

涉及 EO-013。先落地管理员配置的公共活动及世界历史，再评估知识网络、组织和长期研究扩展。

- 依赖：S5 多人事务和授权模型稳定。
- 退出条件：一个公共事件可由配置发布、到期、结算并追踪历史；个人与世界的效果均可审计；事件链深度和总量有上限。
- 经济、政治、文明模拟另行设计与容量验证，不作为 MVP 完成条件。
- 已有自治世界 tick 和公共事件的本地原型，尚不代表 S6 已完成；后续开发按 GitHub issue 跟踪。

世界运行时的本地 D1 集成测试覆盖迁移、显式启动后的无玩家 Cron、延期任务、重复触发、暂停、CAS 元数据和 batch 回滚；对应 [issue #2](https://github.com/ticoAg/earth-online/issues/2) 和 [issue #3](https://github.com/ticoAg/earth-online/issues/3)。安全的管理员服务留待 issue #4，当前原型不代表可以部署生产环境。

延期任务切片完成记录（2026-10-30，EO-013 子集）：`scheduleWorldJob` 接受带幂等键、到期 tick、来源和规则版本的公共任务，`advanceDueWorld` 在事务中结算任务、事件及后续任务；实现见 [runtime.ts](../../src/world/runtime.ts) 和 [迁移](../../migrations/0003_world_jobs.sql)。[测试](../../tests/world-jobs.test.ts)覆盖无玩家 30/100 天、重复与冲突、并发、关闭重开、暂停、预算、有限重试、版本和事务失败。`npm run verify` 通过类型检查、53 项测试及两组各 1,000 角色模拟；`npm run test:d1` 的 7 项测试通过，Node 22.16 下 D1 集成也通过。此切片为离线游戏公共事件；认证、生产部署及管理操作审计仍待实现。

## 默认产品决策与未决项

以下是当前研发默认值，仍可按产品决策调整。沿用 MVP 默认：真实行动记录配合独立游戏际遇；现实时间；自由文字仅作私人备注；初始潜变量不用敏感资料推断；P0 无真人匹配；不设强制统一排名。

以下问题在对应阶段开始前写入决策记录：

| 问题 | 当前默认或约束 | 决策时点 |
| --- | --- | --- |
| 际遇分支与奖励内容 | 奖励属于游戏状态；需要有可拒绝或完成的明确语义 | S1 切片设计 |
| 积累成就的日期口径 | S1 使用 3 个不同 UTC 日期，不要求连续；网页需清楚展示口径 | S1/S3 |
| 认证提供方与角色数量 | 先明确账号归属，禁止从请求正文信任角色所有权 | S2 |
| 记录更正与删除后的派生状态 | 需决定回放、重算或保留审计策略 | S2 |
| 部署环境与容量目标 | 不预设未经测量的性能结论 | S3/S4 |
| 多人关系与共享范围 | 私密默认、双方明确同意 | S5 |

## 每个切片的完成记录

实现记录应列出：关联 EO 编号、输入与输出契约、变更文件、成功与失败场景、验证命令和结果、剩余限制。仅将已通过验收的切片标记完成；其余阶段继续保留为待实现。
