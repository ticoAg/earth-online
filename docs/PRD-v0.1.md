# 地球 Online（Earth Online）

## 产品需求文档 PRD · V0.1

**产品类型：** 网页端多人现实人生模拟游戏  
**核心技术：** 规则引擎、事件驱动、概率计算、状态模拟  
**AI 依赖：** 无  
**当前阶段：** 概念设计与核心机制规划

---

## 一、产品概述

### 1.1 产品定位

地球 Online 是一款以现实人生为原型的多人在线模拟游戏。

玩家通过创建角色、录入个人背景与人生事件参与游戏。系统通过人物属性、隐藏特性、现实规律的近似模型、行为积累、环境条件及概率机制，对玩家行为产生的影响进行计算。

玩家可以通过长期行为形成能力、习惯与人际关系，并在特定条件下触发际遇、突破、特殊事件及稀有成就。

每位玩家的发展并不完全确定，也不会因为完成相同的行为而必然得到相同的结果。

### 1.2 核心理念

**玩家决定行为，世界遵循规则，际遇存在不确定性，经历塑造未来。**

游戏应遵循以下原则：

1. **非线性成长：** 能力不一定随投入匀速增长，可能存在瓶颈、停滞、顿悟与突破。
2. **个体差异：** 相同行为对不同玩家可能产生不同影响。
3. **长期因果：** 过去的行为与经历可能在未来产生延迟影响。
4. **概率性际遇：** 满足条件不等于必然获得结果。
5. **玩家相互影响：** 不同玩家可以通过交流、合作、帮助或竞争改变彼此的发展。
6. **世界共享：** 部分事件可以影响其他玩家甚至整个游戏服务器。
7. **机制优先：** 尽量由底层规则产生结果，而非依赖预设剧情。
8. **纯算法驱动：** 核心玩法不依赖大语言模型或 AI Agent。

### 1.3 现实与游戏的边界

游戏包含两类信息：

- **现实记录：** 用户自行申报的真实经历、行为及个人资料。
- **游戏推演：** 规则引擎根据这些输入计算出的属性变化、事件机会与模拟结果。

两者必须明确区分。

模拟出的相遇、健康变化或科研突破，不能直接当作现实中已经发生的事实。游戏世界中的数值与概率也不能被解释为对真实个人能力、健康或命运的科学评估。

## 二、核心游戏循环

### 2.1 基础流程

1. 玩家注册账号，创建地球 Online 角色。
2. 选择或填写初始背景、兴趣、人生经历等信息。
3. 系统建立角色初始状态，生成部分隐藏特性。
4. 玩家通过结构化界面记录新的行为或事件。
5. 系统根据行为和历史状态更新人物属性。
6. 规则引擎检查潜在的事件触发条件。
7. 符合条件的事件进入概率计算。
8. 玩家收到新际遇、成长反馈、选择机会或成就通知。
9. 玩家与其他玩家互动，产生新的事件。
10. 新的状态继续影响未来的发展。

形成以下循环：

**行为输入 → 状态变化 → 条件满足 → 概率计算 → 际遇或反馈 → 玩家选择 → 新的行为**

### 2.2 时间机制

游戏时间以现实时间为基础，但不要求服务器持续逐秒模拟所有玩家。

采用：

- 事件发生时即时计算。
- 持续性行为按记录周期结算。
- 长期状态通过时间差按需计算。
- 特殊日期和延迟事件通过定时任务触发。
- 不活跃玩家优先采用惰性结算。

## 三、人物与属性系统

### 3.1 可见属性

玩家可查看部分成长信息，例如：

| 领域 | 属性示例 |
| --- | --- |
| 知识 | 数学、语言、自然科学、编程 |
| 技能 | 写作、烹饪、摄影、沟通 |
| 生活 | 活动习惯、作息、生活经验 |
| 探索 | 旅行经历、环境熟悉度、探索经验 |
| 社交 | 联系、合作记录、共同经历 |
| 研究 | 学科基础、命题研究进度、研究经验 |

属性应按具体领域建模，避免仅用智力、魅力等单一数值评价玩家。

### 3.2 隐藏属性

游戏需要存在部分玩家不可直接查看的内部变量。

例如：

- 领域学习适应性
- 知识关联倾向
- 经验迁移倾向
- 学习反馈敏感性
- 探索倾向
- 社交互动倾向
- 特定情境下的机会识别倾向
- 环境适应特性
- 研究突破准备度

隐藏属性可以来自初始化、行为积累、环境作用和特殊事件。

**设计要求：**

- 不完全固定，可以随经历变化。
- 不存在能够决定所有结果的万能属性。
- 不应简单区分优等角色与劣等角色。
- 不能被解释为系统准确测出了玩家现实中的天赋。
- 不公开精确数值，但可通过角色表现体现差异。

### 3.3 非线性成长

成长需要支持：

- 熟练度积累
- 边际收益递减
- 学习瓶颈
- 技能遗忘与恢复
- 跨领域迁移
- 环境修正
- 习惯形成
- 阶段性突破

同一属性的成长效率可以因人物状态、行为类型、学习方式和相关知识基础而改变。

## 四、行为与事件系统

### 4.1 结构化事件输入

第一版不要求系统理解任意自然语言。

玩家从预设的行为类别中选择，填写必要参数，并可添加文字备注。

主要事件分类：

| 类别 | 行为示例 |
| --- | --- |
| 学习 | 阅读、课程学习、练习、考试 |
| 研究 | 探索命题、实验、发表成果 |
| 工作 | 就业、项目、创业、转岗 |
| 社交 | 结识、交流、互助、合作 |
| 生活 | 运动、休息、烹饪、培养习惯 |
| 探索 | 旅行、徒步、参与新活动 |
| 创造 | 写作、绘画、音乐、制作作品 |
| 人生节点 | 毕业、搬家、重大个人决定 |

每条行为应包含事件类型、时间、持续时长及适用参数。

文字备注只用于个人记录，不参与第一版的自动规则判断。

### 4.2 事件触发来源

系统需要支持：

1. 玩家主动提交事件。
2. 属性达到某种状态。
3. 多个条件同时满足。
4. 时间经过或预约事件到期。
5. 人际关系发生变化。
6. 玩家所处环境变化。
7. 其他玩家的行为产生影响。
8. 世界公共事件触发后续变化。

### 4.3 事件规则结构

一条规则至少包含：

- 规则 ID
- 事件类型
- 前置条件
- 条件组合关系
- 触发概率
- 冷却时间
- 触发次数限制
- 事件结果
- 属性变化
- 后续事件
- 成就关联
- 规则版本

规则应尽量通过配置维护，而不是为每个事件单独编写程序。

## 五、际遇与概率系统

### 5.1 际遇定义

际遇指在特定时间、环境和人物状态下，可能发生的具有一定后续影响的事件。

例如：

- 偶然接触新的兴趣领域。
- 遇到愿意分享知识的玩家。
- 获得参与项目的机会。
- 在长期研究中发现新的思路。
- 因既有习惯而具备应对突发事件的经验。
- 通过旧关系获得新的合作机会。

### 5.2 概率计算机制

事件触发分为两步。

**第一步：条件筛选**

判断玩家是否满足事件发生的必要条件。

**第二步：概率计算**

根据相关属性、历史经历、当前环境与随机因素计算发生概率。

满足条件只代表事件有机会发生，不代表一定发生。

### 5.3 长期积累与延迟反馈

部分行为不会立即产生显著结果。

例如持续学习数学：

- 逐渐增加知识与技能熟练度。
- 建立不同知识点之间的联系。
- 在特定阶段形成研究瓶颈。
- 遇到新的知识或人物时，有机会产生突破。
- 突破产生新问题，继续影响后续研究。

过去的积累必须能够在未来事件计算中发挥作用。

### 5.4 随机性控制

为保证可玩性，概率机制需要具备：

- 可重复测试的随机种子。
- 概率上下限。
- 触发冷却机制。
- 防止重复领取奖励。
- 区分常见与极稀有事件。
- 防止通过高频重复输入恶意刷取际遇。
- 事件结果可追踪、可解释。

游戏概率是设计模型，不声称代表现实中的真实发生率。

## 六、知识、研究与顿悟系统

### 6.1 知识结构

知识不只是一条总经验值，而是由多个领域、技能及其依赖关系组成。

例如：

数学 → 微积分 → 数学分析 → 特定研究领域

同时允许建立跨学科关联。

### 6.2 研究行为

玩家可以选择一个研究方向，持续投入时间与资源。

研究系统需要保存：

- 研究领域
- 前置知识
- 累计研究经历
- 已尝试的方向
- 已获得的线索
- 研究协作关系
- 当前研究阶段

### 6.3 顿悟与突破

顿悟由多种条件共同影响：

**知识积累 + 知识关联 + 当前问题 + 环境刺激 + 随机条件**

顿悟本身不代表研究成功。

可以形成：

发现新思路 → 尝试验证 → 形成成果 → 获得认可

前期可以采用有限的研究主题、技术树和预设知识关联规则，不要求程序真正创造或验证全新的数学定理。

### 6.4 稀有研究成就

例如：

- 数学研究者
- 独立证明者
- 跨学科探索者
- 重大理论突破
- 传说级数学家

现实中的菲尔兹奖等真实荣誉，必须与游戏虚构奖励分离。真实奖项的成就需要核实，不能仅凭概率计算直接授予。

---

## 七、多人交互与人际关系系统

### 7.1 玩家关系

系统需要支持：

- 相识
- 好友
- 合作伙伴
- 师徒或指导关系
- 团体成员
- 共同研究者

关系由双方实际互动和明确选择建立，不应仅凭系统推断。

### 7.2 互动事件

玩家之间可以触发：

- 知识分享
- 经验传授
- 合作研究
- 项目协作
- 资源帮助
- 共同活动
- 长期关系事件

事件可能同时影响多名玩家。

### 7.3 贵人与关键际遇

不预先为某名玩家指定固定的「贵人」身份。

只有当人物交互确实对另一名玩家产生重要帮助时，才可能形成相应的关系记录或游戏成就。

同一段互动可能对双方产生不同结果。

### 7.4 社交安全

玩家的匹配、相遇、消息与资料共享必须有相应的授权和隐私控制。

系统不应在未经双方同意的情况下，宣称玩家现实中已经相识或建立某种关系。

## 八、成就系统

### 8.1 成就类型

| 类型 | 示例 |
| --- | --- |
| 人生经历 | 第一次独立旅行 |
| 学习成长 | 掌握一项新技能 |
| 持续积累 | 长期坚持某项活动 |
| 探索发现 | 开启新的兴趣领域 |
| 社交关系 | 建立长期合作关系 |
| 研究突破 | 解决特定研究任务 |
| 隐藏成就 | 满足特殊条件组合 |
| 多人协作 | 与其他玩家共同完成目标 |
| 世界级成就 | 对共享游戏世界产生重要影响 |

### 8.2 稀有度

普通、稀有、史诗、传说及隐藏成就。

稀有度由设计规则、达成难度及实际分布共同决定，不单纯由随机中奖概率决定。

### 8.3 成就规则

- 支持单条件、多条件、时间跨度和事件链。
- 支持公开、隐藏和渐进解锁。
- 支持多人共同成就。
- 支持防重复触发。
- 部分特殊成就需要验证。
- 成就可以展示触发依据及关联历史。
- 允许根据规则版本管理平衡性调整。

## 九、共享世界系统

### 9.1 世界状态

除了个人属性，系统应维护共享的世界状态，例如：

- 游戏区域
- 公共活动
- 团体与组织
- 知识与技术解锁状态
- 公共事件
- 世界成就
- 服务器历史记录

### 9.2 世界级影响

玩家行为可以在满足条件后改变局部或公共状态。

例如：

某些玩家合作完成研究任务 → 新知识节点解锁 → 其他玩家获得新的研究路线。

第一版不必实现完整经济、政治、生态或文明模拟。

### 9.3 公共事件

系统管理员可以配置具有时间、范围和条件限制的世界事件。

后续再发展由规则自动触发的区域事件与全服事件。

## 十、网站功能与页面需求

### 10.1 核心页面

1. **首页：** 游戏介绍、世界入口及登录注册。
2. **角色创建：** 昵称、初始背景、兴趣与基础设定。
3. **角色面板：** 可见属性、技能、成长与称号。
4. **事件记录：** 玩家选择并提交结构化行为。
5. **人生时间线：** 历史事件、际遇和成长记录。
6. **成就图鉴：** 已解锁、未解锁与隐藏成就。
7. **成长与知识树：** 领域学习、技能与研究进度。
8. **际遇中心：** 待处理事件、特殊机会和后续选择。
9. **关系页面：** 好友、合作伙伴和共同经历。
10. **世界页面：** 公共事件、世界状态和服务器历史。

### 10.2 交互风格

整体采用游戏化界面，但保持网页操作的简洁性。

可以融入：

- RPG 角色档案
- 成就弹窗
- 技能树
- 人生任务日志
- 隐藏事件
- 世界公告
- 人生经历分享卡片

视觉风格暂不确定。

## 十一、技术要求

### 11.1 核心限制

**第一版不接入任何 AI 模型或 AI 服务。**

游戏计算由传统程序实现，包括：

- 条件判断
- 数学公式
- 概率抽样
- 状态机
- 规则引擎
- 事件队列
- 关系计算
- 图结构与依赖关系
- 定时及惰性结算

### 11.2 推荐技术

- 前端：Next.js + TypeScript
- 后端：TypeScript / Node.js
- 数据库：PostgreSQL
- 规则系统：自研可配置规则引擎
- 异步处理：数据库任务队列，必要时引入 Redis
- 事件机制：事件驱动架构
- 部署：普通云服务器，无 GPU 需求

### 11.3 核心数据对象

至少包括：

- Player：玩家账号
- Character：角色资料
- Attribute：角色属性
- HiddenTrait：隐藏特性
- Skill：技能
- KnowledgeNode：知识节点
- PlayerEvent：玩家提交事件
- Rule：事件规则
- TriggerResult：触发计算结果
- Encounter：际遇
- Relationship：人物关系
- Achievement：成就定义
- AchievementUnlock：成就解锁
- WorldState：共享世界状态
- EventDependency：事件依赖关系

事件需要记录发生时间、数据来源、规则版本、随机种子及处理结果，支持审计和调试。

### 11.4 性能与可靠性

- 不持续逐秒运算所有玩家。
- 事件触发时按需计算。
- 只执行与事件有关的规则。
- 对长时间未活跃的玩家采用惰性结算。
- 支持事件去重、失败重试和事务一致性。
- 防止事件链无限循环。
- 关键规则可以进行批量模拟与统计测试。
- 通过数据库索引和缓存提升规则检索效率。

---

## 十二、隐私与公平性

玩家可能提交真实的人生资料，因此需要：

1. 尽可能少收集敏感个人信息。
2. 默认将个人事件和隐藏属性设为私人数据。
3. 允许玩家选择公开哪些经历与成就。
4. 支持记录修改、导出与删除。
5. 明确区分自行申报、游戏验证与模拟生成的信息。
6. 防止用户借助重复提交事件刷属性和成就。
7. 不以隐藏分数评价真实人格、健康或人的价值。
8. 提供社交举报、屏蔽和互动同意机制。

## 十三、开发优先级

### P0：最小可玩版本（MVP）

**目标：验证规则能否产生有趣且可解释的个体成长与随机际遇。**

包含：

- 玩家注册与创建角色
- 基础可见属性
- 隐藏特性初始化与更新
- 结构化事件输入
- 属性成长与衰减规则
- 概率触发系统
- 基础际遇和后续选择
- 成就解锁
- 人生事件日志
- 规则测试工具

建议第一版仅包含：

- 5～8 个核心属性领域
- 20～30 种行为事件
- 10～20 种隐藏特性
- 30～50 条际遇规则
- 50 个成就
- 1 个简化的研究与突破系统

以上是建议的初始规模，可按实际开发进度调整。

### P1：多人世界

- 玩家关系
- 双人事件
- 知识与资源分享
- 合作任务
- 多人共同成就
- 区域与公共事件
- 关系影响后续际遇

### P2：复杂世界模拟

- 多领域知识网络
- 长期研究命题
- 复杂社会关系网络
- 组织与经济系统
- 玩家驱动的知识传播
- 重大世界事件
- 文明发展与长期历史

## 十四、第一阶段验收标准

第一版至少应能够验证：

1. 玩家创建角色后，可以得到具有差异性的隐藏状态。
2. 提交结构化学习事件后，角色相关属性正确变化。
3. 两名状态不同的角色执行相同行为时，可以出现合理差异。
4. 长期积累可以改变后续事件概率。
5. 突破事件必须满足前置条件，并通过概率判断。
6. 成就能根据事件和属性组合正确解锁。
7. 事件日志能够解释一次结果的触发过程。
8. 重复提交同一事件不会导致重复奖励。
9. 无需 AI 和持续高频模拟，也可以完成完整游戏循环。
10. 可以使用自动化测试角色模拟大量事件，发现规则冲突及不合理的概率分布。

## 十五、待确定的产品决策

以下事项尚未最终确定：

**1. 现实与模拟的比例**

以记录真实经历为主，还是允许玩家在独立的虚拟世界中进行额外选择和推演？

**2. 初始隐藏属性的生成方式**

采用随机初始化、角色背景修正，还是允许玩家在创建时选择某些成长倾向？

**3. 游戏时间与现实时间的关系**

完全同步，还是部分研究、际遇和长期任务可以使用加速游戏时间？

**4. 属性公开程度**

玩家应能看到多少底层数据？隐藏机制应保留多少可解释性？

**5. 多人互动的形式**

是现实用户主动交流，还是通过服务器提供的际遇、活动及合作机制建立关系？

**6. 游戏目标**

以人生收藏、探索和成就为主，还是加入更明确的长期任务与世界级目标？

## 十六、最终产品愿景

地球 Online 的目标不是让所有玩家追求同一种成功路径。

它希望通过一套规则自洽、具有概率性和长期因果影响的模拟机制，让玩家体验到：

- 不同的人拥有不同的起点与发展条件。
- 努力和积累可能产生延迟回报，但不保证特定结果。
- 人与人之间的偶然交集可能改变未来。
- 特殊际遇往往由长期准备、环境和机遇共同形成。
- 每个人都拥有不同的发展路线。
- 普通玩家也可能通过自身行动影响他人的人生与共享世界。

**最终目标：构建一个不需要 AI 生成剧情，却能够通过人物、事件与规则交互不断产生新故事的地球 Online。**

**核心设计原则：用有限的规则，创造丰富而难以预先确定的经历。**
