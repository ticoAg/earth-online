# 地球 Online · 核心机制设计 V0.1

> 状态：设计草案。对应 [PRD V0.1](PRD-v0.1.md)。第一版完全不使用 AI 模型。所有数值与概率均是**游戏规则参数**，并非现实健康、天赋或人生成功率的科学预测。

## 1. 核心设计原则

1. **事件驱动而非逐帧模拟。** 玩家提交结构化行为，或系统收到定时、关系、公共事件时才计算。
2. **输入、事实和推演分离。** 用户自述事件不自动变成被验证的现实事实；游戏内生成的际遇也不能假称现实发生。
3. **状态有历史。** 当前属性由先前事件推导；重要变化必须能追溯触发规则、版本与计算结果。
4. **条件和概率分开。** 满足前置条件才有机会抽样，抽样不保证发生。
5. **多路径成长。** 不用一个全能「智力」「魅力」决定人生。领域知识、习惯、情境和关联网络分别建模。
6. **隐藏但公平。** 隐藏属性改变玩家的成长方式和机会，不能先验决定玩家的终局，也不能作为现实能力测评。
7. **有限规则产生组合。** 优先设计可复用的行动、状态、条件、结果，而不是编写大量独立剧情。

## 2. 世界与角色状态

### 2.1 状态层级

| 层级 | 数据 | 第一版 |
| --- | --- | --- |
| 账号 | 身份、授权、隐私偏好 | 必需 |
| 角色 | 昵称、公开资料、游戏天数 | 必需 |
| 显性属性 | 数学知识、写作技能、探索经验等 | 必需 |
| 隐藏特性 | 领域适应性、知识连接倾向等 | 必需 |
| 持续状态 | 疲劳（游戏值）、专注、习惯、冷却 | 必需 |
| 知识图 | 已解锁节点、前置关系、关联边 | 简版 |
| 人际关系 | 双向同意、共同事件、协作记录 | P1 |
| 世界状态 | 公共事件、区域、研究解锁 | P1/P2 |

### 2.2 初始属性约定

- 显性熟练度：0～100，按具体技能分组（不是人的综合价值评分）。
- 隐藏特性：0～1 的游戏潜变量；不向玩家展示原始值。
- 时间资源：提交行为需要事件发生时间与持续分钟数，并受冲突及合理时长约束。
- 持续状态：按状态自身的衰减规则在**相关事件发生时或查询时**结算，无需每分钟调度。
- 最初只用 5～8 个可见领域和 10～20 项潜变量；不要提前堆砌数百维。

角色可以在创建时获得一个基于可重复随机种子的、均衡分布的初始特性向量。初始特性应可因后续活动而缓慢变化；不得根据用户真实健康、年龄、性别等敏感信息推测能力优劣。

### 2.3 第一版建议的领域

| 领域 | 可见指标 | 内部影响因素示例 |
| --- | --- | --- |
| 数学 | 基础、分析、证明、研究经验 | 知识连接、练习适应、复盘倾向 |
| 语言 | 阅读、写作、表达 | 练习方式、长期使用习惯 |
| 创造 | 作品经验、领域技能 | 跨域关联、尝试新路径 |
| 探索 | 户外经验、地图探索 | 探索偏好、环境熟悉度 |
| 生活 | 烹饪、家务、日常技能 | 习惯维持、练习效率 |
| 社交 | 共同行动、协作经历 | 社交习惯、情境匹配（不表示人的「价值」） |

**注意：** 游戏不应通过用户自行填报的活动推断其免疫力、心理疾病或真实医学风险；如需要健康玩法，先保持为明确虚构的游戏状态。

## 3. 行动、状态与成长

### 3.1 事件输入

行动必须结构化。例：学习数学分析 90 分钟，练习方式为解题；自由文本只是个人备注，不参与规则计算。

事件被接受后首先检查：身份、字段合法性、可用时间、是否重复、配额、是否需要对方同意。接受事件 ≠ 确认现实事实，只表示可以纳入当前游戏规则计算。

### 3.2 一个可实现的成长函数（暂定）

设：

- m：当前领域熟练度（0～100）。
- h：经校验的有效学习小时数。
- a：领域适应系数（0.75～1.25），由隐藏特性与训练方式共同决定。
- q：方法和当前状态修正（0.5～1.2）。
- b：领域基础学习速率（配置项）。
- c：软上限，初版使用 100。

一次行动的熟练度增量：

~~~text
delta = b × min(h, h_cap) × a × q × max(0.05, 1 - m/c)
new_mastery = clamp(m + delta, 0, c)
~~~

这是**可调试的游戏近似公式**，而非真实学习曲线。它的意义是让熟练度接近上限时增长放缓，但仍保留后期改进空间。不同学习方式可以影响不同知识节点，不能用无差别的「学习时间」提高所有技能。

### 3.3 知识图与跨域关联

用知识节点和前置条件表达内容，而不是把数学当成单个经验条：

~~~text
代数基础 ─┐
          ├→ 微积分 → 数学分析 → 研究方法 → 数学命题研究
函数基础 ─┘
                                  ↑
                                证明方法
~~~

- 节点有掌握程度及其前置要求。
- 行为指向一个或多个具体节点；达到前置要求后才可学习进阶内容。
- 与另一领域的学习或交流可能新增「关联边」。
- 关联边仅代表**游戏中建立的知识联系**，不声称真实科学发现。

### 3.4 不同角色的差异从何而来

同样 90 分钟学习可能导致不同的成长，因为：

- 既有知识的匹配程度不同。
- 学习方式、当前持续状态不同。
- 隐藏适应系数不同且随经历变化。
- 是否积累了与新内容相关的知识连接不同。

这里应该产生**不同路线**，而非「某玩家永远领先」。成长差异的均值、方差与上限必须经过离线模拟平衡。

## 4. 际遇引擎

### 4.1 三个阶段

1. **候选生成：** 接收到事件，仅查找订阅该事件类型或相关属性的规则。
2. **确定性筛选：** 检查必要条件、时序、冷却、权限、参与者同意、事件配额。
3. **概率与结果：** 对通过筛选的候选生成一次可审计的随机结果；成功则创建际遇或待选项，失败仍保留既有成长。

**不允许用户反复点击「再抽一次」对同一事件重投。**

### 4.2 际遇与既成事实不同

际遇可以有三种类型：

- **提示机会：** 系统推荐一项可能有价值的行为（如「参加数学讨论会」）。只有玩家主动行动才能形成行为记录。
- **游戏内事件：** 角色在**模拟层**遇到一个研究线索、特殊任务等，标注为虚构游戏事件。
- **真实多人事件：** A 邀请 B 共同学习；只有 B 接受，双方才形成共同经历。

系统不能直接宣布「你现实里遇到了一位贵人」或「你已经获得某个现实奖项」。

### 4.3 概率模型

事件通过条件检查后，计算：

~~~text
p = clamp(base_rate × preparation_factor × context_factor × relation_factor, 0, event_cap)
roll = stable_server_random(event_id, rule_id, rule_version, opportunity_index)
triggered = roll < p
~~~

- 各系数都有明确上下限。
- 抽样只在一条**唯一有效的触发机会**出现时执行。
- 每条规则指定冷却与周期预算，避免大量微小事件刷概率。
- 事件抽样结果及版本写入审计记录，支持排错和复现。
- 玩家可看到触发的主要条件，但不必公开全部隐藏数值与随机种子。

概率大小需由模拟结果校准。**不要**把游戏中的 2% 解释为现实研究突破的真实发生率。

## 5. 顿悟系统：一种特殊际遇

顿悟不是「研究时间达到 1000 小时自动通关」。

### 5.1 前置条件

以数学研究为例：

1. 数学分析、证明方法的节点掌握度达到最低要求。
2. 在具体研究主题有足够积累（按有效研究事件计量）。
3. 已建立若干相关知识连接，或刚发生一次相关信息接触。
4. 没有处于该规则冷却期。
5. 当前研究事件有效，且通过针对该机会的概率抽样。

### 5.2 结果与后续

成功触发意味着「形成一个值得进一步验证的新想法」，而非「证明某个真实数学猜想」：

~~~text
研究行动
  → 研究经验增长
  → 可能建立新知识连接
  → 检查顿悟规则
      ├─ 未触发：继续积累
      └─ 触发：获得【研究线索】
                    → 选择验证 / 求助 / 暂缓
                    → 触发后续研究事件
                    → 可解锁游戏内成就
~~~

真实学术奖项（例如菲尔兹奖）不得通过模拟概率直接授予。虚构传说成就需有独立名称与说明。

### 5.3 失败也要有价值

- 未触发不减少既有知识。
- 未验证成功的尝试可以增加「排除路径」和研究经验。
- 研究的长期回报不应完全由随机抽样决定。
- 允许中途更换研究主题，避免使玩家为单条路线无限重复输入。

## 6. 多人交互（P1）

**人与人的关系是双向同意的状态，不是系统自动推断的私人事实。**

- 匹配条件：共同活动、可公开兴趣、区域（用户同意的粗粒度范围）与互动意愿。
- A 发起协作邀请 → B 确认 → 生成共享事件 → 分别结算 A/B 的贡献与状态变化。
- 知识分享、共同研究等行为可以形成新的知识连接与后续合作机会。
- 「贵人」作为玩家回顾视角的称号或双方认可的共同成就，不能先于真实互动预设。
- 任何人可拒绝、撤回互动同意、屏蔽与举报。

## 7. 成就设计原则

| 类型 | 条件方式 | 示例 |
| --- | --- | --- |
| 记录类 | 单次有效事件 | 第一次独自旅行 |
| 积累类 | 多个不同日期的有效事件 | 稳定学习习惯 |
| 关联类 | 多学科节点与关系组合 | 知识交汇 |
| 研究类 | 达到一系列研究状态 | 第一条研究线索 |
| 多人类 | 双方确认的共享事件 | 初次联合研究 |
| 传说类 | 极高难度的游戏内条件 | 边界探索者 |

单靠自我申报的行为，不得直接解锁需要真实世界验证的官方奖项或学历/证书。成就应保存规则版本、触发事件 ID 和可解释的主要条件。

## 8. 核心体验示例

玩家甲、乙都提交相同的「数学分析练习 90 分钟」：

- 甲的当前知识基础较完整，获得更多节点掌握度。
- 乙因近期在物理学到相近概念，可能额外形成一条跨学科知识连接。
- 两人都继续增长，但不一定得到同样的际遇。
- 某天乙在游戏内参加一次主动选择的跨学科交流，满足顿悟条件，并在概率检查后获得「研究线索」。
- 如果选择进一步验证，才进入后续研究任务。没有任何一步要求调用 AI。

## 9. MVP 取舍与边界

**做：** 单人角色、领域技能、隐藏特性、10～20 个事件类别、规则引擎、三种基本际遇（机会/模拟/记录）、成就、事件日志、研究线索。

**暂不做：** 真实人生预测、真实疾病诊断、未经许可的玩家匹配、AI 对话、无限自由文本理解、完整经济体系、真正的原创数学定理自动验证。

先保证 10 个不同初始角色，在同样与不同的行为序列下，产生**有解释依据、可复现且不完全相同**的成长与事件轨迹，再逐步扩容。

## 10. 下阶段必须确定的问题

- 用户填报的事件是「现实档案」还是「给平行角色的行动指令」？建议 UI 明确分栏。
- 角色初始化是完全随机还是可配置起点？建议只对游戏潜变量随机、其他可见背景由用户自选。
- 冷却、时长和自述真实性如何平衡？建议先每日上限与重复检测，后续加可信度分级。
- 什么样的可解释度既保留隐藏惊喜，又让玩家信任结果？建议公开规则类别与触发原因，隐藏精确权重。
